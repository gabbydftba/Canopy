How HTTP Has Changed

The protocol has gone through major upgrades over the last few decades to keep up with modern technology. As websites became more complex, newer versions of HTTP were developed to make communication between browsers and servers more efficient.

HTTP/2 improved how multiple requests could be sent over the same connection, allowing webpages to load more efficiently. HTTP/3 introduced QUIC, a newer transport protocol that uses UDP instead of TCP. QUIC is designed to reduce delays and handle multiple streams of information more efficiently.

HTTP/0.9: The Early Version

The earliest version of the protocol, introduced in the early Web, was later named HTTP/0.9. It was famously called the "one-line protocol" because it was incredibly simple compared to what we use today.

A browser could only send a single line of text consisting of the word GET and the file path. There were no headers, metadata, or status codes. The protocol mainly transferred HTML documents and closed the network connection when the transfer was finished.

GET /index.html

HTTP/1.0: The First Major Upgrade

HTTP/1.0 arrived in the mid-1990s. It added headers, status codes, and support for different types of content. These improvements gave browsers and servers more information about requests and responses.

Unlike HTTP/0.9, HTTP/1.0 could transfer more than just HTML documents. It made communication more flexible and helped support the growing number of websites.

HTTP/1.1: Persistent Connections

When HTTP/1.1 became the web standard, one of its biggest improvements was persistent connections. In older versions, a browser generally had to open and close a new connection for each resource on a webpage, which could cause delays.

HTTP/1.1 allowed a single connection to stay open so multiple files could be requested over it. It also introduced improved caching controls, allowing browsers to reuse files they had already downloaded instead of repeatedly requesting the same resources.

HTTP/2: Multiplexing

As websites evolved into complex applications, HTTP/1.1 could create bottlenecks because requests often had to wait for earlier responses on a connection.

HTTP/2 addressed this by introducing multiplexing. This feature allows multiple streams of information to travel at the same time over one connection.

HTTP/2 also uses a binary format and compresses headers to reduce repeated information. It originally included a feature called Server Push, although this feature is now deprecated in modern browser implementations.

HTTP/3: QUIC

Even with the improvements of HTTP/2, communication over TCP could still experience delays when packets were lost. This can cause head-of-line blocking at the transport layer.

HTTP/3 uses a newer transport protocol called QUIC. QUIC runs over UDP and supports independent streams. This means that a lost packet in one stream does not necessarily stop all other streams from continuing.

QUIC also supports faster connection setup and is designed to handle changing network conditions, including when mobile devices switch between networks.
